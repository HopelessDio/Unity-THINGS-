# Veil Walker: default two-handed sword

Source design: `VeilWalker_Preview09_HoodCollar.blend`.
Editable production source: `VeilWalker_Model01.blend`.
Actual default render: `Previews/VeilWalker_TwoHandSword_Model01.png`.

Default loadout is **sword only, held with both hands**. The arm stance is the exported bind pose, so the character shows the two-handed grip even without an animation controller. The optional gun asset is retained for later and is not equipped or regenerated by the default build.

## Independent models

- `Assets/Models/Player/VeilWalker_Model01.fbx`: character only; 23 bones, normalized skin weights, mask, covered neck, and long burgundy cape.
- `Assets/Models/Player/LeanKnight_Longsword01.fbx`: original approved sword, unchanged. Grip-centered origin.
- `Assets/Models/Player/VeilWalker_Pistol01.fbx`: independent dark-steel pistol, grip-centered origin, and `Muzzle` transform pointing down the barrel.

The character has `SwordSocket_R`, `GunSocket_L`, `SwordSocket_L` and `GunSocket_R`. `SwordOffhandGrip`, underneath the right sword socket, marks the lower grip position for the supporting left hand. The sword stays one independent weapon object; it is not duplicated for the second hand.

## Unity assets

After **Assets → Refresh**, the one-time preparation request creates URP materials and these prefabs under `Assets/Prefab/Player/VeilWalker`:

- `VeilWalker.prefab`: rigged character with empty weapon slots.
- `VeilWalker_Sword.prefab`: independent approved sword.
- `VeilWalker_Equipped.prefab`: default character holding one sword with both hands; no gun.

If needed, run **Survivor → Prepare Veil Walker Two-Handed Sword**.

`PlayerWeaponEquipment` exposes `SwordOffhandGrip` for later animation/IK, as well as optional gun sockets. Weapon roots attach with zero local position/rotation and unit scale. The socket determines grip orientation. Sword attacks must animate both hands together or use the supporting grip as an IK target.

The asset preparation alone does not change the scene. `Game.unity` now binds the approved character and sword via `PlayerModelVisual` on `Player3d`. It creates a `VeilWalkerVisual` child in the editor and at runtime, fits its height and feet to the existing capsule, and corrects imported facing for mouse aiming. Generated editor previews are not serialized into the scene, preventing duplicate visuals.

Movement, aiming, dash, health, capsule and Rigidbody stay on the gameplay root. The old capsule renderer, `DarkKnightVisual`, and projectile shooter are disabled for the sword-only loadout. There is no sword damage or swing animation yet.

**Survivor → Install Veil Walker in Game Scene** performs the same installation and verifies that there is exactly one character visual, a sword, and no equipped gun.

## Animation status

Sword motion refinement: explicit blade rotations avoid LookRotation roll changes near vertical cuts; hand movement follows a curved Bezier arc. Active swings occupy more of the unchanged total clip duration (ending at 70%), so cuts are more readable. Entry elbow bend planes blend from the incoming pose instead of switching abruptly. Queued hits hold follow-through and capture it into the next wind-up; a click during recovery starts the next attack from the current pose. Single attacks still blend back to the original running guard. Slash traces have rounded joins. Damage, assist, run, dash and spacing are unchanged. Additional checks sample blade/elbow continuity at 120Hz and exact joins between queued poses.

Attack targeting polish: strike intent comes from current keyboard/stick input before the smoothed visual turn finishes, falling back to current facing while idle. Soft targeting chooses an alive, unobstructed nearby enemy within a 70-degree half-cone and 2.85m search radius, prioritizing alignment over distance. Wind-up can correct aim; each combo strike retargets independently, but active swings keep a stable direction. Facing unlocks during recovery, and attack turns use faster damping while retaining the existing smooth locomotion turns. Movement, click-only input, animation poses, damage, hit reach and dash cancellation are unchanged. This is our Hades-inspired assist, not a claim to reproduce Hades' exact targeting algorithm.

Retry lifecycle fix: `PlayerModelVisual` attempts creation on enable, again in Start, and after its owning scene's sceneLoaded event. OnEnable may run before scene.isLoaded during Retry; post-load rebuilding prevents a permanently missing model. Existing instance guards prevent duplicates and event subscriptions are removed on disable. `PlayerRetryValidation` is a pending-file-gated editor regression test that verifies initial Play plus two real death/Retry reloads, including fresh health, rendered model, sword, locomotion, attack and afterimage components.

Sword combo: left-click (or gamepad west button) starts diagonal sweep -> returning sweep -> heavy straight overhead cut. Each new press starts/queues one strike; holding does not auto-attack. One press can buffer the next strike, and the combo resets after 0.3s idle. Default damage is 15/15/35 with a 2.5m reach; the heavy hit has a narrower cone and stronger knockback. Damage occurs only in the active swing window, once per EnemyHealth per strike, respecting ArenaObstacle blockers and existing hit-flash/kill systems. Facing locks to the strike heading; WASD still moves, and dash cancels the attack. A short ivory sword-tip trace accompanies active swings. `PlayerSwordAttack` runs after locomotion and before dash snapshots; the supporting hand is solved to the shared sword grip. Approved run/dash/ash effects are preserved. Editor checks validate 1584 animation poses and isolated damage probes away from arena objects.

Ash visibility adjustment: original puffs were very small/low-alpha and close to the floor. Current puffs use 30-50cm starting sizes, 50-65% starting alpha, 320-500ms lifetimes, and centres 22cm above the floor. Takeoff emits 12 and landing 8 particles; the 40-particle cap remains. The soft cloud profile is fuller. Validation advances the particle simulation and checks surviving size/alpha plus baked billboard geometry. Ivory streak and afterimages are unchanged.

Ghost + ash presentation: afterimages are preserved unchanged. The old 80cm-wide colored ribbon becomes a soft 6.5cm ivory-white streak with a 75ms lifetime. `PlayerDashTrail` emits 8 small ash particles at takeoff and 5 on landing, using a single reused world-space particle system with a 40-particle cap. Puffs grow softly and disappear within 180-320ms. `DashIvoryStreak.mat` and `DashAsh.mat` use the procedural URP `DashWisp` shader; no texture downloads or gameplay/collider changes. Dash speed, timing, animation and cooldown are unchanged.

Dash afterimages: `PlayerDashAfterimages` captures the posed skinned character and independent sword after locomotion in LateUpdate. Up to six frozen world-space mesh snapshots appear during a dash (~32ms spacing), fading over 260ms using a crimson-white, cloudy rim shader. Meshes are pooled, snapshots never instantiate players/components/colliders, and owned meshes are cleaned up on destruction. `Assets/Resources/DashAfterimage.mat` keeps the custom URP shader available in builds; tint/opacity can be tuned there. Dash physics and approved animation are untouched. The installer checks body snapshot scale, frozen world position, pool bounds, cleanup, and shader compilation.

Dash animation: read-only `PlayerMovement.IsDashing`/`DashProgress` drive a visual pose overlay. Run phase holds during the active dash; a 35ms blend-in and 110ms recovery blend preserve the existing cycle. The dash uses a 26-degree lean, compressed pelvis, a leading leg picked from the current step, a trailing leg, braced two-handed sword and raised trailing cape. Supporting-hand IK is restored after blending to keep contact with the separate sword. Physics speed/duration/cooldown, health and trail logic are unchanged. Editor validation samples 720 blended dash poses, checking grip, signed foot order, unchanged physics root and return to the original run pose.

Smooth direction changes: `PlayerAim` eases yaw with a 0.09s damping time and 1080 degrees/second cap instead of snapping. It finishes the last requested turn when input stops. WASD velocity remains responsive/unchanged. Foot world-locking pauses during turning so local forward-run poses flow continuously rather than repeatedly replanting; steady running resumes ground locks. Approved stride, sword carry and latest ~19.4cm ankle spacing are retained. Turn checks cover 40 diagonal/reversal/wrap cases at two fixed timesteps.
